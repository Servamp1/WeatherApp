# Вопросы для защиты

1. **Почему Kotlin и XML?**

   Это требования задания; XML описывает Views, Kotlin — поведение.

2. **Какие три экрана есть?**

   MainActivity, CitySelectionActivity и AuthorsActivity.

3. **Как открываются экраны?**

   Через Intent и startActivity; finish возвращает к предыдущей Activity.

4. **Откуда берётся погода?**

   Из HTTPS endpoint Open-Meteo /v1/forecast без API-ключа для учебного некоммерческого использования.

5. **Какие параметры передаются?**

   Координаты города, пять current-показателей, Celsius, м/с, мм и timezone=auto.

6. **Как читается JSON?**

   JSONObject получает current и current_units; значения и единицы проверяются до создания WeatherData.

7. **Почему интерфейс не зависает?**

   Сеть работает в ExecutorService, UI обновляется в главном потоке через runOnUiThread.

8. **Как хранится город?**

   Его строковый идентификатор сохраняется в SharedPreferences. По умолчанию — Москва.

9. **Как защищены данные от старого ответа?**

   Каждый запрос получает номер; UI принимает только результат последнего номера.

10. **Как определяется ветер?**

   Угол делится на восемь секторов со смещением 22,5°; 0° и 360° дают север. Это направление, откуда дует ветер.

11. **Что означают осадки?**

   Количество в мм за предшествующий интервал current.interval, обычно 900 секунд. Это не вероятность и не суточная сумма.

12. **Что происходит без интернета?**

   Появляется сообщение об ошибке, кнопка обновления снова доступна.

13. **Что происходит при повороте?**

   Activity пересоздаётся, старый запрос отменяется и не обновляет уничтоженный экран, новый экран запрашивает выбранный город.

14. **Почему нет Retrofit и базы данных?**

   Для одного запроса и одного сохраняемого значения достаточно стандартных средств Android.

15. **Что реально проверено?**

   Сборка APK, Android Lint, три модульных теста и реальные ответы API. Запуска на устройстве не было.
